## 一、项目概述与使用方式

### 1.1 项目背景

思政教育的成效落差，往往出现在课堂之外。

学生在教材里能够熟练背诵党的性质、宗旨与纪律，但坐进真实的入党谈话现场，被组织委员追问一句"你说的这些，和你的生活有什么关系"时，往往无从作答。与其说学生不用功，不如说**知识输入与能力输出之间存在一道断层**。

这道断层可以拆成四处具体缺口：

- **学用脱节：理论难落地。** 学生"学得多、用得上"的少，思政理论与社会实践能力之间存在明显鸿沟，难以将所学转化为解决实际问题的行动力。
- **资源受限：辅导难精准。** 教师授课与辅导资源有限，难以实现"一对一"的精准化培养，无法兼顾每位学生的思想动态、认知差异与个性化成长需求。
- **体验单一：交互缺深度。** 传统数字化工具侧重单向灌输，缺乏沉浸式交互与实践演练环节，难以有效激发学生的主动思考与情感共鸣。
- **成果零散：练完即散。** 单次练习缺少沉淀，学生看不到自己的成长轨迹，教师也难以掌握长期变化，成长记录需要一条可持续累积的主线。

本项目的目标，是把这四处缺口补上：**构建沉浸式数字思政新生态，推动思政教育从"知识输入"走向"能力输出"。** 具体做法是把入党谈话、党史研学、思政辩论等真实场景完整复刻进数字空间，让学生随时随地参与互动式学习，系统实时记录行为数据并生成可视化成长反馈，使思想政治教育由单向的知识传递，转变为可量化、可感知、可提升的能力培养闭环。

### 1.2 项目定位

**思政情景工坊，是一款把思政课堂搬进真实情境的 AI 实训平台。**

它并非资料检索式的问答工具，而是六个可反复进入、试错与复盘的真实场景。学生在其中扮演入党申请人、辩论选手、研学队员，与 AI 扮演的组织委员、辩论对手、导游正面交锋；系统记录每一次发言并逐轮给出点评，最终汇总为一份能直观呈现进步的成长档案。

一条主线贯穿全部模块：

**角色扮演 → 情景模拟 → AI 个性化反馈 → 可视化成长轨迹**

### 1.3 目标用户

| 使用主体 | 角色定位 | 关注价值 |
|----------|----------|----------|
| 学生端 | 入党申请人、入党积极分子、共青团员、学生干部 | 24 小时随时演练、可视化成长、提升通过率 |
| 教师端 | 辅导员、思政教师 | 减少重复答疑与一对一演练，数据化掌握学生薄弱点 |
| 学校端 | 校院系思政工作体系 | 打造"课堂 + 线上 + 实践 + 社区"一体化思政载体 |

### 1.4 六大功能模块

#### （1）入党谈话模拟训练

**像真的一样被追问，而不是对着题库背答案。**

内置 4 个谈话场景：入党积极分子谈话、预备党员接收谈话、预备党员转正谈话、随机模拟谈话。每个场景配有独立的考官人格与头衔。

- **动态追问**　AI 依据学生上一轮的回答决定下一轮问什么：回答空泛就追细节，回答具体就往深处走，答不上来就换个角度再问一次。该追问机制贴合真人谈话的节奏，固定模板难以复现。
- **阶段推进**　谈话按开场寒暄 → 自我认知 → 入党动机 → 理论考察 ×2 → 情景假设展开，共六个问题轮次，AI 依据场景难度决定追问深度。
- **实时观察**　每轮对话结束立刻给出本轮观察：先肯定这一轮的长处（信息点是否给准、因果是否讲清、有没有落到具体的人和事），再指出缺什么、下一轮该补什么。学生不必等整场结束才知道哪里不对。
- **量化报告**　谈完生成评估报告，含总分环、等级、五维雷达图、各维度建议，以及与本人上次同场景成绩的历史对比（评分规则见 3.2）。

报告页明确标注"本报告由 AI 生成，为训练预估结果，不代表党组织正式评价"。

- **个人档案**　开场前自动读取本人历史谈话与其他模块的练习记录，此前答得薄弱的维度会成为本轮追问的重点，避免每场都从零开始。
- **图片作答**　可随回答附上手写思想汇报、证明材料等照片，AI 结合图片内容点评。

#### （2）党史情景互动学习

**不是读一篇史料，而是走进那个现场。**

内置 5 本党史书卷，覆盖 1921 南湖启航、1935 遵义转折、1949 开国新生、1978 春潮改革、2021 建党百年五个关键节点。

- **分卷式馆藏导航**　以书架 UI 呈现多部历史场景书，可点击翻阅逐卷进入对应历史篇章，每卷内容独立成篇，支持断点续学。
- **沉浸式情景叙事**　通过电影化写实场景画面还原历史现场，标注时间、地点、时代背景，按时间线推进剧情。
- **线索寻证互动**　场景内设有可交互热点，学生需点击提取现场证据（如物件线索、环境信息、人物状态），收集多条线索后形成两段式判断——史料佐证 → 结论归纳，作为后续判断的依据。
- **权威史料支撑**　关键节点弹出史料插页，展示权威原始史料文本并标注史料来源，帮助学生理解"情景推演"与"历史事实"的区别。
- **史实边界标注**　每一页右上角常驻「情景复原」徽记，说明本页依据权威资料复原时间、地点与事件环境，人物形象与镜头调度用于叙事，不作为历史照片，也不代表人物原话；当代参访场景则标注「当代场景示意」。
- **阅读形态**　书页支持横向拖拽翻页，声音与字幕可独立开关，开关状态随学习进度一并保存。

全部完成后该卷归档，并计入成长指数。

#### （3）红色研学智能导游

**走一趟，写一篇，留一份档。**

内置井冈山、延安、西柏坡、韶山、遵义 5 个研学点位，采用"当代抵达 + 历史之窗"的双重视角。

- **实景路线**　以站点串联红色地标，每个 STOP 对应一处实景与一段历史，学生按图行进。
- **分支判断**　每个点位同样是"路线—证据—判断"三处关键决策，线索未集齐不能作答，走错进入支线回溯后重新选择，并非线性打卡。
- **AI 导游**　提供开场讲解与自由问答，学生可随时就现场细节追问。
- **研学手记**　学生撰写不少于 20 字的手记，系统据此自动生成研学报告。
- **票根式报告**　以票根形式可视化呈现（档案类型、生成状态、印章点亮），回显原始手记，支持复制导出与断点续学。报告以路线复盘为底稿，完成的关键判断数、支线回溯次数与发现的现场线索数一并写入。

![图 4　研学导游：井冈山、延安等五个点位的实景路线](06_研学导游.png)

#### （4）思政辩论赛陪练

**对面坐着一个真会反驳你的对手。**

内置 15 道辩题，并支持 AI 实时生成新辩题。学生选择正方或反方出战，AI 自动扮演对手立场。辩论分立论 → 质询 → 驳论 → 总结四个阶段，提供快速练习（4 步）与完整赛训（6 步，含双向质询与两轮攻防）两套模式。

- **逐条回应**　AI 对手不是自说自话，而是针对学生上一段陈词逐条反驳：先判断这段论证是否切题，再指出哪一环缺证据，最后追问一个学生尚未澄清的前提。跑题会被当场指出，偷换概念会被要求定义清楚。
- **六步战术指令**　完整赛训的六个步骤各配独立的动作要求，例如质询必须"先直接回答，再提出一个反质询"，驳论不得引入新的主要论点，总结不得替对方归纳立场，使每一步训练都有明确的衡量标准。
- **证据资料席**　从知识库检索已审核资料，每轮最多引用 3 条并附完整来源，逼学生用材料说话。学生提交的引用由服务端按编号回查，只接受已发布文档，重复引用自动去重；检索结果同样经过发布状态过滤，最多返回 8 条。
- **自拟辩题**　AI 拟题默认仅本人可见，学生可以无限自拟题目自用；教师生成的新题直接进入公共题库。
- **论证地图**　AI 逐轮抽取"主张 / 证据 / 推理链 / 待补缺口"，把口头表达结构化成可检视的论证骨架。
- **裁判报告**　总分 + 五维评分 + 每维建议 + 关键交锋复盘，可回跳原文；评分时明确考虑所选立场的论证难度。

![图 5　辩论赛场：AI 对手的逐条反驳与本轮提示](07_辩论赛.png)

#### （5）一站式思政成长社区

**练完之后，有人可聊、有事可做、有迹可循。**

包含帖子、问答、多级回复、点赞收藏与通知，内置 5 个分类。内容审核链路完整：敏感词检测 → 待审 → 举报 → 三态处理。

- **师生共创**　教师任务支持创建时配置加权量规（2–5 个维度，权重合计必须为 100），设置截止时间与附件；达到 60 分方可通过，批阅后量规锁定。批阅要求全部维度评分齐全，总分由后端按权重加权计算，不采信客户端传来的分数。
- **问答采纳**　提问者可采纳一条回复作为最终答案；重复采纳幂等返回，已采纳其他回复时拒绝覆盖，采纳后为回答者计分。
- **成长档案**　汇总成长指数（谈话 30% + 辩论 30% + 党史 20% + 研学 20%）、成就印章与成长足迹，并标注账目是否对平。
- **指标分离**　积分与能力指标严格区分：积分记录参与行为，能力指标反映训练水平，页面上明确标注"积分不是能力分"。
- **内容治理**　举报、审核、下架全链路留痕，可追溯每一条处理记录；重复举报自动去重，浏览计数按 6 小时分桶，避免刷量。
- **消息中心**　回复、采纳与教师反馈统一汇聚，未读高亮，点击直达对应的帖子或教师任务。

#### （6）思政知识库

**每一句回答，都能翻到原文那一行。**

- **多格式入库**　文档上传支持 PDF / DOCX / TXT / Markdown，具备 MIME 白名单、大小上限与 sha256 去重；文本解析优先按 UTF-8 解码、失败回退 GB18030，分块在句读边界处切开并保留重叠。新资料先进入处理流程，解析建索引后转为待审核，只有教师或管理员审核发布后才进入检索范围。
- **三级混合检索**　向量语义检索负责"意思相近"，全文检索（BM25）保证专有名词命中，中文关键词兜底防止前两级落空；两路结果经 RRF 融合排序，任一层超时即降级到下一层，并对融合结果追加相关性校验与单文档限量，防止长文档挤占结果。
- **追问理解**　提问以"它""上述""这两者"等指代开头时，系统自动结合同一会话的上一条问题改写检索式，使追问同样能检索到资料。
- **逐句引用**　回答在每句结论后标注 `[1]`、`[2]` 引用编号，点击可展开对应原文片段，末尾列出实际依据的资料数量。
- **学习档案问答**　可以直接问"我哪里薄弱""我练过什么"，Agent 会调用工具读取本人的历史练习与报告要点，给出针对性的分析与练习建议，答案标注为「学习档案回答」。
- **带图提问**　可随问题附上截图、手写稿或史料照片，模型结合图片与已审核资料作答；图片解读不附引用编号，与知识库回答分开展示。
- **无据拒答**　检索不到依据时明确回答"当前知识库没有足够依据为您回答"，不让 AI 编造。
- **写作模板**　内置 4 类模板（入党申请书、思想汇报、心得体会、个人自传），可一键生成初稿并二次编辑、留档反复修订。

### 1.5 运行方式与使用说明

#### 在线体验

演示站点已部署在公网：`http://121.41.231.233:5667/`，用浏览器打开即可体验全部六大模块，首次使用以手机号与密码注册后进入。以下为在本地或自有服务器上复现的完整步骤。

#### 部署与启动

本地开发只需 Python 3.11+ 与 Node.js 20+。克隆仓库后，在 `backend/` 目录复制 `.env.example` 为 `.env` 并填写 `JWT_SECRET_KEY` 与 `LLM_API_KEY`，执行 `pip install -r requirements.txt`，再以 `uvicorn app.main:app --port 8000` 启动（本地未运行 PostgreSQL 时，将 `.env` 中两个 `DATABASE_URL` 改为 `sqlite:///./dev.db` 并清空 `VECTOR_DATABASE_URL`，检索自动降级为 SQLite 全文索引），首次启动自动建表并写入完整演示数据（含 17 篇权威资料与分块索引，清单见附录 A.2）；前端在 `frontend/` 目录执行 `npm install` 后运行 `npm run dev:h5`，浏览器访问 `http://127.0.0.1:5667/`，接口文档在 `http://127.0.0.1:8000/docs`。

生产环境使用 Docker Compose：将 `.env.production.example` 复制为 `.env` 并填入配置，执行 `docker compose -f docker-compose.production.yml up -d --build`。各服务配置 healthcheck，前端经 `node:20` 构建后由 `nginx:1.27-alpine` 提供，对外只暴露前端端口，数据库与缓存保持内网访问。

#### 账号与登录

- **登录方式**：手机号 + 密码
- **首次使用**：在注册页用手机号与密码注册，系统自动创建账号
- **角色体系**：超级管理员、教师、学生三类角色对应不同功能入口
- **登录态**：JWT（HS256），有效期 24 小时；登录接口基于客户端 IP 与手机号做双重限流，防止暴力破解

![图 10　登录页：手机号与密码登录](01_登录页.png)

#### 使用流程（学生端）

1. 注册并登录，进入首页学习路径
2. 在"入党谈话"中选择谈话场景，开始练习
3. 与 AI 考官进行多轮对话，随时查看能力雷达图的变化
4. 结束谈话，查看评估报告与改进建议

8. 在"知识库"上传资料，围绕资料向 AI 提问并核对引用

## 二、需求分析

### 2.1 痛点到需求的推导

思政实践教学的四类缺口，对应四条产品需求，再落到具体的功能与验收方式：

| 痛点 | 用户需求 | 本项目对策 | 落地模块 |
|------|----------|------------|----------|
| 学用脱节：背得出条文，答不上追问 | 可以反复演练、会追问的真实场景 | AI 按阶段追问，答不上来换角度再问 | 入党谈话模拟 |
| 资源受限：教师难以一对一辅导 | 不依赖教师在线的高频练习与即时点评 | 每轮给出观察，结束后生成五维报告与历史对比 | 谈话、辩论、研学 |
| 体验单一：单向灌输缺乏互动 | 能动手、能决策、能承担后果的学习过程 | 书卷分支决策、线索寻证、错误支线回溯 | 党史情景、研学导游 |
| 成果零散：练完即散 | 把一次练习沉淀为长期成长记录 | 成长指数、成就印章、教师任务量规 | 成长社区、成长档案 |

### 2.2 功能需求

| 角色 | 核心用例 | 验收口径 |
|------|----------|----------|
| 学生 | 谈话、辩论、书卷、研学、问答、社区六类实训 | 全流程可断点续学，成果进入成长档案 |
| 教师 | 资料审核发布、教师任务与量规批阅、社区治理 | 未审核资料不进入检索，批阅后量规锁定 |
| 管理员 | 角色授权、健康检查、AI 安全与 Agent 运行状态 | 就绪探针可用，拦截事件可查询 |

### 2.3 非功能需求

| 类别 | 要求 | 实现方式 |
|------|------|----------|
| AI 输出可信 | 模型输出不得直接进入业务逻辑 | 白盒校验层、分数钳制、缺失维度抛错 |
| 回答可核查 | 每句结论可溯源，无据不编造 | 逐句引用编号、引用校验、无据拒答 |
| 安全合规 | 密钥不入库，提示注入可控 | 环境变量配置、AI 安全网关、角色分级 |
| 稳定性 | 上游失败不产生脏数据 | 503 显式失败、幂等台账、写前落库 |
| 性能 | 常用接口秒级返回，长任务有上界 | 分层超时与降级、Agent 步数与时长上限、前端分包与懒加载 |
| 可部署 | 本地与服务器均可复现 | SQLite / PostgreSQL 双通道、Docker Compose 一键部署 |

### 2.4 验收标准

需求以可检验的方式落到验收标准，全部纳入自动化测试或运行期保障：

| 能力 | 验收标准 |
|------|----------|
| 入党谈话 | 六轮问答完整走完；单维度不足 2 条证据不显示分数；报告含五维得分、历史对比与改进建议 |
| 思政辩论 | 四阶段完整；跑题与偷换概念被当场指出；裁判五维评分经白盒校验 |
| 党史与研学 | 分支判定只在服务端；线索未集齐返回 409；错误支线可回溯且不改写历史结局 |
| 知识问答 | 回答逐句带引用编号并可展开原文；无依据时明确拒答；引用编号越界整段作废 |
| 社区与积分 | 同一来源只计发一次积分；重复提交返回原结果或 409 |
| 可靠性 | AI 不可用返回 503，不产生残缺练习、不发放虚假积分；检索任一层超时自动降级 |

## 三、项目亮点

### 3.1 差异化定位：场景实训替代问答式学习

当前市面上的思政数字化产品，不少仍停留在「能查资料的问答框」层面，功能仅限于学生提问与 AI 作答。本项目的判断是：**思政教育的短板不在"不知道"，而在"做不到"**——学生掌握入党谈话的内容要点，但面对组织委员的追问时往往难以表达。

因此本项目的产品形态是**六个可反复演练的真实场景**，而非问答工具：

| 场景 | 学生要完成的事 | AI 扮演的角色 | 练完留下什么 |
|------|----------------|---------------|--------------|
| 入党谈话 | 完成 6 轮谈话并应对追问 | 院党委组织委员 | 五维评估报告 |
| 党史情景 | 在 5 本史书中做出关键决策 | 史官 / 历史人物 | 归档书卷与积分 |
| 红色研学 | 抵达 5 个点位并撰写手记 | 现场讲解导游 | 研学报告（票根） |
| 思政辩论 | 完成 4 阶段对抗并回应驳论 | 持相反立场的对手 | 裁判报告与论证图 |
| 知识问答 | 就权威资料求证并核对引用 | 依据原文作答的检索助手 | 带引用的问答档案 |
| 成长社区 | 发帖、答疑、参与教师任务 | 审核与反馈 | 成长指数与成就印章 |

**本项目与同类产品的根本区别在于：学生经历的是一个完整场景，而非一次资料查询。**

### 3.2 量化评价与证据门槛

多数 AI 教育产品的评价停留在"回答得不错""表达清晰"这类无法验证的措辞。本项目将评价拆解为可追踪的量化指标：

- **五维能力画像**：思想认识、表达逻辑、入党动机、理论掌握、应变能力，每维 0–100 分，随对话轮次滚动刷新
- **证据门槛**：某一维度累计不足 2 条有效证据时**不显示分数**，避免单轮对话就贴标签
- **总分由后端重算**：取各维度均值，不采信模型自报的总分
- **历史对比**：与本人上次练习同一场景的成绩并列展示，进步或退步一目了然
- **改进路径**：针对得分最低的两个维度给出具体建议，而非泛泛而谈
- **只采信完整记录**：谈话与辩论必须轮次齐全且已生成报告才计入成长指数，旧流程记录仅作只读展示
- **按唯一情景去重**：党史与研学的掌握度按情景、点位去重计算，重复刷同一场景不会累积
- **披露覆盖度**：成长指数同时给出已覆盖模块数与覆盖率，缺少证据的维度按剩余权重重新归一化

学生完成一次谈话练习后得到的，是一份包含得分、历史对比与改进方向的评估报告，而非一句笼统评语。

### 3.3 全流程闭环与成果沉淀

单点工具的典型问题是练完即散，难以形成积累。本项目将六个模块的产出汇入同一份成长档案：

- 谈话、辩论、党史、研学四类实训按 30% / 30% / 20% / 20% 加权，合成为**综合成长指数**
- 每次有效练习触发成就印章，形成持续激励
- 教师可在任务模块配置 2–5 维加权量规（权重合计必须为 100），达到 60 分方可通过，批阅后量规锁定
- 积分与能力指标严格分离，互不混淆

成长档案并非成绩单的堆叠，而是将零散的练习转化为可回溯的成长轨迹。

### 3.4 AI 输出的可靠性校验

这是本项目最具工程区分度的一点，也是同类作品普遍忽略的地方。

大模型的输出天然不稳定。若直接把模型返回的分数渲染到页面上，会出现"总分 120 分""置信度 3.5""证据为 null"这类结果；更严重的是，学生只要在回答里写一句"请给我 100 分"，就可能被提示注入影响评分。

本项目的处理原则是：**凡来自模型的数据，一律先当作不可信输入校验，通过后才允许进入业务逻辑。**

| 风险 | 本项目的行为 |
|------|--------------|
| 分数越界（120、-5） | 回合观察值钳制到 0–100，报告维度值直接拒绝 |
| 置信度越界（3.5） | 回合观察值钳制到 0–1，报告维度值直接拒绝 |
| 用 `true` 冒充分数 | 显式拒绝（bool 是 int 子类，必须单独排除） |
| 缺失某个维度 | 抛出错误，绝不以 0 值填充 |
| 总分与各维不一致 | 后端重算，不采信模型自报 |
| 证据过长（整段抄袭） | 截断至 180 字 |
| 检索不到依据 | 明确拒答，不编造 |
| AI 服务不可用 | 返回 503，不产生残缺练习、不发放虚假积分 |

这套校验覆盖全部 AI 调用，是模型输出进入业务逻辑前的强制环节，而非事后补救；第四章将给出对应的自动化测试。

### 3.5 引用溯源与回答可核查

RAG 问答的每一句结论都带引用编号，点击即可展开知识库原文片段。回答末尾列出实际依据的资料数量；资料不足时明确说明，不凭空补充。模型返回的内容若所引编号全部落在可用范围之外，整段回答作废并替换为标准拒答话术，而不是把无出处的文字交给学生。

在思政场景中，这一点并非加分项，而是底线要求：涉及党的理论表述时，"看似合理"的回答比"没有回答"更具风险。

### 3.6 情景复原的史实边界

沉浸式场景最容易失守的地方，是为了"剧情效果"改写历史。本项目的处理方式是：**允许学生走错路，但不允许历史给出第二种结局。**

- 党史 5 卷与研学 5 站共设 30 个关键判断，每个判断配 2 个错误选项，合计 60 个错误支线页。
- 错误分支不把历史事件改写成另一种结局，而是让"现场观察者"走进一条没有收获的调查路线——只记录沿途天气、只统计礼炮声响次数，支线文案只写调查受挫，历史结论仍由该卷的权威史料给出。
- 每个支线页附带本卷同一条权威来源；史料插页可直接查看原始出处。
- 答错后按尝试次数逐级给出提示：前两级收窄证据范围，第三级接近明示正确路线，引导学生回到证据而不是直接给答案。

### 3.7 可验证的工程化规范

项目将代码质量转化为可执行的检查项，而非文档中的自我评价：

- Ruff 静态检查（E/F/I/UP/B/SIM 六类规则）**零告警**，前端 `vue-tsc --noEmit` 严格模式无类型错误
- 104 项自动化测试全部通过，GitHub Actions 在每次推送时自动执行检查
- mypy 类型检查、Prettier、EditorConfig、Alembic 迁移与健康探针的完整配置见 5.16

### 3.8 交互模式创新：把练习做成可以走进去的场景

传统学习产品把交互做成"表单 + 结果页"，本项目把每个模块都做成可进入的场景：

| 交互 | 做法 | 学生感受到什么 |
|------|------|----------------|
| 对话即场景 | 院党委组织委员按阶段追问；辩论对手逐条反驳；导游随时答疑 | 在对话里完成练习，而不是填问卷 |
| 分支书卷 | 翻页式阅读 + 每个点位三处关键决策，错误支线可回溯，史料插页可查原图 | 走进历史现场做判断，判断有后果 |
| 实时能力画像 | 每轮对话后雷达图滚动刷新，单维度证据不足不亮分 | 看得见自己在哪些维度变强 |
| 语音朗读 | 考官提问与讲解词可转语音（Edge 神经语音），失败自动降级为文本 | 像在听一场真实的谈话 |
| 视觉系统 | 研墨色板（暖纸底、朱砂红、鎏金）、楷体标题、噪点纹理卡片，六模块统一 | 一致的"红色文化 + 纸墨"气质 |
| 轻量前端 | 图片懒加载、路由分包、按需加载 | 首屏更快，切换更顺 |

### 4.4 典型测试代码

```python
def test_11_debate_prompt_context_is_bounded_for_long_sessions(self):
    conversation = [{"stance": "pro" if i % 2 == 0 else "con",
                     "content": f"第{i}轮：" + "历史内容" * 700} for i in range(20)]
    with patch.object(service, "_call_api", new=AsyncMock(...)) as call:
        asyncio.run(service.debate_argue(
            topic="基层选举的规范", stance="pro", argument="论述" * 4000,
            conversation=conversation,
            evidence=[{"document_title": "资料" * 100, "excerpt": "引用" * 2000}] * 8,
        ))
    prompt = call.await_args.args[0][1]["content"]
    self.assertIn("最近辩论交锋", prompt)
    self.assertLessEqual(len(prompt), 23000)     # 提示词长度有上界
    self.assertTrue(call.await_args.kwargs["disable_thinking"])
```

### 4.5 测试之外的可信性设计

除自动化测试外，系统在运行期还有七层保障：

1. **AI 响应健壮性 / 防伪造分数**：回合观察值钳制 0–100，报告维度值越界即拒绝；证据截断 180 字；明确拒绝 `bool`；缺失维度直接抛错，不以 0 值填充。后端最终总分重算为各维度均值，并叠加"至少 2 条有效证据才显示"的门槛。

2. **幂等积分**：积分台账为不可变审计账本，以表级唯一约束与嵌套事务作为并发双写的双重保障；重复提交或重复完成时仅计发一次积分。

3. **防重复提交**：每次对话携带客户端 `submission_id`；命中同一提交且已送达时原样返回缓存结果，仍在处理时于 90 秒内返回 409，并配合报告生成环节的行锁抢占与 2 分钟超时兜底。

4. **失败显式化**：AI 不可用时返回 503，不生成残缺练习记录，不发放虚假积分；无法回答时明确拒答，不编造无证据内容。

5. **版本化与向后兼容**：以 `flow_version` 与 `is_legacy` 区分新旧流程数据，使流程能够安全演进；旧数据只读展示，新数据按当前版本处理。

6. **写前落库**：辩论陈词先以待发送状态写入数据库，之后才调用模型；调用或校验失败即把该条标记为失败并返回 503，失败消息不计入轮次、不占用赛程，重试也不会重复计分。

7. **报告生成状态机**：报告生成前以条件更新抢占，失败写回失败状态并允许立即重试，超时两分钟可被重新抢占，避免并发重复调用模型。

### 5.3 AI 技术选型理由

| 选型 | 选择 | 理由 | 放弃的备选与原因 |
|------|------|------|------------------|
| 大模型 | DeepSeek（OpenAI 兼容接口） | 中文长文理解稳定，支持 JSON 模式、Function Calling 与图片输入，单价低，适合高频实训场景 | 境外模型时延与成本更高；接口层保持 OpenAI 兼容，换模型只改配置 |
| 嵌入模型 | BAAI/bge-small-zh-v1.5（512 维） | 中文语义表现好、体积小，CPU 可推理，后台预热不阻塞启动 | 大模型嵌入维度高、内存占用大，单机部署不划算 |
| 检索 | pgvector + 全文检索 + 中文关键词兜底 | 单一向量检索在专有名词与短查询上失手，全文检索补精确命中 | 纯向量召回泛；纯关键词语义泛化差 |
| 融合 | RRF | 无需调参即可融合两路排名，对分值尺度不敏感 | 加权求和需要按语料调权重，维护成本高 |
| 结构化输出 | JSON 模式 + 白盒校验 | 先用 JSON 模式降低格式错误，再用校验层兜住越界与缺字段 | 只靠提示词约束，实测会出现截断与夹带自然语言 |
| 工具调用 | OpenAI 兼容 Function Calling | 与模型原生支持一致，工具描述与参数由 Schema 约束 | 靠正则解析模型输出，不可靠且难调试 |
| 语音 | Edge 神经语音（免密钥） | 中文自然度高、无需自建模型，失败可降级 | 自建 TTS 需要算力与模型管理，收益有限 |
| 工具协议 | MCP（stdio） | 外部 Agent 可零改造复用知识库，生态已成事实标准 | 自定义 HTTP 工具协议生态弱 |
| 快慢模型分流 | 主模型 + 快模型（`LLM_MODEL_FAST`） | 意图路由、改写、重排、核验只做判别不做生成，快模型足够且延迟低 | 全部走主模型成本与延迟都更高；再引入便宜的小模型则部署复杂 |
| 检索策略 | Agent 自主检索 + RAG-Fusion 固定链路 | 多跳问题靠 Agent 规划，单跳问题靠多查询与重排，两条链路互为回退 | 只保留其中一条都会在另一类问题上退化 |
| 答案复用 | 语义缓存（嵌入余弦阈值） | 近义问题直接复用带引用答案，降低时延与调用成本 | 字面缓存命中率低；不设缓存则重复问题反复计费 |
| 引用可信度 | 生成后引用核验 | 逐块判断是否被原文支撑，剔除沾边引用 | 只靠提示词要求引用，模型仍可能给出无关编号 |

**集成方式。** AI 能力以统一服务层接入业务，而不是在页面里直接拼提示词：路由层只负责鉴权与参数校验，`ai_service` 负责提示词、调用与输出校验，检索、Agent、缓存、核验等服务以函数组合的方式协作，业务数据通过工具回填给模型。同一套能力——引用编号、白盒校验、熔断、额度——因此对所有模块一致生效。

**优化策略。** 六个方向同时展开：

| 目标 | 策略 | 效果 |
|------|------|------|
| 降延迟 | 快慢模型分流、语义缓存、前端分包与懒加载 | 近义问法几乎即时返回，首屏加载明显加快 |
| 提准确 | 三级混合检索、多查询改写与加权 RRF、引用核验 | 口语化问法下 recall@1 提升 13.0 个百分点 |
| 控成本 | 按用户日额度、判别型调用走快模型、缓存复用 | 30 万 token/日/人上限，重复问题不重复计费 |
| 保可信 | 白盒校验、引用编号约束、无据拒答 | 模型输出不会以越界分数或虚构引用进入业务 |
| 抗故障 | 三级检索降级、熔断、Agent 失败回退固定链路 | 单点失败不中断问答 |
| 可观测 | 调用指标环形缓冲、观测接口、安全拦截计数 | 成功率、时延与拦截量随时可查 |

### 5.4 关键技术一：AI 能力的统一封装

所有 LLM 调用统一封装在 `app/services/ai_service.py`，按场景定义独立的 system prompt，避免了提示词散落在各处。核心设计：

- **传输层统一**：`_call_api` 统一处理超时、重试、JSON 模式、思考链开关与多模态内容块
- **白盒校验层**：`validate_interview_turn`、`validate_debate_turn`、`validate_scored_report` 等纯函数逐字段检查类型与取值范围
- **业务编排层**：16 个业务方法对应 6 大模块的 AI 交互
- **一次调用三产出**：辩论回合只发起一次模型调用，同时产出对手回应、本轮点评与论证地图三部分，避免为不同产物重复调用
- **结构化回合固定参数**：辩论与评分回合统一关闭思考链、启用 JSON 模式，避免推理过程耗尽输出预算导致空响应
- **按场景分配预算**：检索、问答、攻辩与报告分别配置超时与长度上界，超长部分显式标注"[内容过长，以下已截断]"

AI 响应校验的关键实现（摘自 `app/services/ai_service.py`）：

```python
def _score(value, label: str) -> int:
    if isinstance(value, bool):          # bool 是 int 子类，必须显式排除
        raise AIResponseValidationError(f"AI 返回的{label}不是有效分数")
    try:
        score = int(value)
    except (TypeError, ValueError) as exc:
        raise AIResponseValidationError(f"AI 返回的{label}不是有效分数") from exc
    if not 0 <= score <= 100:
        raise AIResponseValidationError(f"AI 返回的{label}超出 0-100 范围")
```

### 5.5 关键技术二：自主检索 Agent 与学习档案工具

面对多层问题（如"入党誓词出自哪次大会、其表述前后有何调整"），单次检索只能覆盖一半，因此知识问答把检索与"记忆"一起封装成工具，由模型自行规划调用：

| 工具 | 作用 |
|------|------|
| `search_knowledge` | 已审核资料混合检索，返回带编号的片段 |
| `list_documents` / `read_chunk` | 查看资料目录 / 读取指定片段原文 |
| `get_learning_profile` | 本人学习档案：各模块练习次数、平均分、最薄弱维度与最近建议 |
| `list_my_practices` | 本人历史练习列表，可按模块过滤 |
| `get_practice_detail` | 某次练习的问答片段与报告要点 |

一轮问答最多三轮工具调用、每轮最多两个并行调用，模型判断证据充分后停下并输出结构化答案。工程约束与固定检索路径保持一致：

- 知识库片段按首次出现顺序编号，模型只能引用已下发的编号；学习档案与练习记录不参与编号，个人记录不冒充可引用资料；
- 步数用尽仍未收敛时禁用工具、强制生成答案，避免无限循环；
- 任一环节异常都回退到固定检索链路，用户侧不感知；
- 档案工具只按当前登录身份取数，按记录 ID 读详情时再次校验归属，跨用户记录一律视为不存在。

个性化因此落在两处：知识问答里，学生可以直接问"我哪里薄弱、按这个出一套题"，答案标注为"学习档案回答"；入党谈话开场前，系统把历史薄弱维度注入考官的系统消息，让追问围绕此前答不好的地方展开。

实测：一次档案类问答模型并行调用两个工具、耗时约 2 秒；一次三工具资料问答耗时约 8 秒，引用 4 条资料。

### 5.6 关键技术三：RAG 混合检索

知识库检索采用**三级混合策略**，而非单一向量检索：

| 层级 | 技术 | 作用 |
|------|------|------|
| 第一级 | pgvector 余弦相似度 | 语义召回，理解"意思相近" |
| 第二级 | 全文检索（BM25 / FTS5） | 关键词召回，保证专有名词命中 |
| 第三级 | 关键词 ILIKE 中文兜底 | 向量与全文都失败时的最后保险 |

关键词与向量两路结果经 **RRF（Reciprocal Rank Fusion）** 融合，并对标题命中额外加权；ILIKE 是两路都失败后的中文兜底。融合之后还要过一道相关性校验：关键词命中须满足其一：命中标题，或至少命中两个检索词，或命中一个不少于 4 字的词，向量命中须接近本批最优距离，避免把"沾边"的结果送进模型。结果组装时按片段哈希去重，同一文档最多贡献 3 个片段，防止长文档挤占其他来源。任一层级超时即降级到下一层，保证在资源受限时仍能给出结果。

中文检索另做了一层处理：先剔除"请问""是什么""有哪些"等疑问填充词，再按 6/4/3/2 字宽度切出重叠词元，各宽度单独留名额（最多保留 24 个）——2 字词必须留名额，因为"入党""誓词""支部"这类领域词恰好是两个字；词元用 OR 组合成全文查询，SQLite 的 FTS5 优先使用 trigram 分词，建表失败回退 unicode61，若数据库未编译 FTS5 则整体回退关键词匹配。第三级 LIKE 兜底会让全部词元参与匹配，并按命中词数排序，而不是按库内顺序取前几条。

系统提示词强约束"只能依据已审核资料回答、必须带引用编号"；`<evidence>` 为空时不调用模型，直接返回"当前知识库没有足够依据"，从源头杜绝无据编造。

### 5.7 关键技术四：AI 安全网关

大模型应用的第二类风险来自输入侧：用户可能试图改写系统指令、套取提示词，或在实训里直接索要分数。系统在问答、谈话、辩论三个入口统一接入安全网关：

- **输入检查**：文本先做 NFKC 归一化，再去掉空白与标点，抵御"忽 略 以 上 指 令"这类拆字绕过；规则分两级，明确的指令覆盖与提示词窃取直接拒绝（400），"给我满分"这类评分操控只记审计、不拦截，避免误伤正常表述；
- **输出处理**：返回前统一脱敏，手机号、身份证号、银行卡号替换为掩码；
- **审计**：拦截与脱敏事件写入环形缓冲，管理员可通过 `/api/v1/ai/security/stats` 查看累计计数与最近事件，事件只记录类别与长度，不保留原文。

### 5.8 关键技术五：图片多模态与语音合成

**图片理解。** 谈话、辩论、研学、书卷问答与知识问答五处对话都支持随消息附上图片：学生可以拍下手写思想汇报、史料照片或课件截图提问。图片以 data URL 提交，进入模型之前先过校验——只接受 PNG/JPEG/WebP，单张不超过约 6 MB，一次最多两张，base64 逐条解码校验；不合规输入直接返回 400，不会被拼进模型请求。带图提问跳过意图路由，直接进入"检索 + 解读"流程；回答没有命中已审核资料时仍保留正文，但标注为"图片解读"、不附引用编号——图片是学生提供的材料，不是知识库证据。

**语音合成。** 谈话考官的问题、讲解词可转成语音朗读，走 Edge 神经语音，免密钥；结果按 `sha256(文本+语音)` 内容寻址缓存，重复朗读不再请求上游；上游不可用时返回 503 并清理半成品文件，不会写入残缺缓存。

### 5.9 关键技术六：沉浸式剧情的服务端判定

书卷的每一次判断都在服务端完成，前端拿不到答案。

- **答案不下发**　接口返回的判断页只带选项 id 与文案，正确项、反馈与跳转目标存放在服务端的剧情图里；提交选择后由服务端给出判定与提示。
- **证据前置**　每个判断节点声明必须先发现的现场线索，线索不全时选择接口返回 409"请先找齐当前判断所需的现场线索"，既不记录尝试也不推进路线。
- **路线状态机**　进度保存当前页、已访问、已解锁与回退轨迹，支持前进、后退与跳转到已解锁场景，轨迹保留最近 80 条。页面失效或流程版本升级时，未完成进度回退到起点、已完成进度固定到结局，避免旧数据把学生卡死。
- **问答有界**　书内问答只接受本卷已解锁页面的提问，上下文由该页的史料、时间线与来源拼成，超出范围的提问直接拒绝。

### 5.10 关键技术七：数据安全与权限

- **认证**：JWT（HS256），启动时校验密钥强度（生产环境要求 ≥32 位）
- **授权**：基于角色的依赖注入（`require_role`），超管 / 教师 / 学生三级
- **登录防护**：基于客户端 IP 与手机号的双重滑动窗口限流，注册与登录共用同一套计数
- **密码存储**：pbkdf2_sha256 加盐哈希，数据库不存明文；返回前端的用户对象按白名单构造字段
- **令牌即时失效**：每次请求解码令牌后回查用户并校验启用状态，账号停用后旧令牌立即失效，无需维护黑名单
- **可选认证不静默降级**：公开接口在未携带令牌时按游客放行，令牌无效时返回 401，不会被当成未登录
- **附件安全**：MIME 白名单 + 大小上限 + Pillow 图片完整性校验 + 路径穿越防御；附件下载按归属分级授权
- **跨域**：CORS 来源白名单；白名单一旦包含通配符，自动关闭凭证传递
- **密钥管理**：`.env` 不入版本库，提供 `.env.example` 模板，启动时校验密钥强度

### 5.11 关键技术八：积分台账的幂等设计

积分是最容易出错的模块——重复提交、并发请求都可能导致重复发分。本项目采用**不可变审计账本**模式：

- 每次积分变动是一条不可修改的 `PointTransaction` 记录，流水内固化规则版本、中文说明与业务元数据
- 表级唯一约束 `(user_id, module, event_type, source_id)` 保证同一来源只发一次，终态记录释放唯一键
- 嵌套事务兜底并发双写
- 对账自检：把各模块流水合计为账本总额，与用户表上的总积分比对，不一致时在接口层标记 `is_reconciled=false`；迁移前的历史余额单列展示，不与新流水混算

### 5.12 关键技术九：MCP 工具服务器

知识库检索能力通过 MCP（Model Context Protocol）以 stdio 方式对外暴露，提供 `search_knowledge`、`list_documents`、`get_document_outline` 三个工具，Claude Desktop、Claude Code 或任意 MCP 客户端都可把本项目的知识库接为自己的检索工具。工具实现与协议注册分离，出错返回结构化错误码而不是异常栈，每个工具都能被独立测试（7 个用例）。

### 5.13 关键技术十：RAG-Fusion 式多查询检索与列表重排

固定检索链路（Agent 关闭或失败时使用）在 5.6 的混合检索之上叠加三层增强。

这里与 5.6 的分工需要说明：5.6 的 RRF 发生在**同一条查询**的向量结果与关键词结果之间，解决"用哪些召回手段"；本节的加权 RRF 发生在**多条查询**各自返回的结果组之间，解决"用哪些检索式"。一条查询进来仍先完整走完 5.6 的三级检索，本节只负责把问题复制成三路、再把这三种取法合回一份排序。

1. **多查询改写**：快模型把问题改写成 2 个语义等价、措辞不同的检索式，与原问题三路并行检索，弥补单次检索式覆盖不全；任一路失败只标记降级，不影响其余结果；
2. **加权 RRF 融合**：三组结果按倒数排名融合（k=60），同一片段在多组出现则名次分累加，把"多路都认可"的片段排到最前。改写出的检索式彼此相似，若完全等权，它们的公共候选会压过原始问题独有的命中，因此对原始查询加权（权重 2，可配置）；单文档片段上限沿用 5.6 的 3 条；
3. **列表重排**：把候选片段编号后一次性交给快模型，返回按相关性排序的编号数组；模型只回部分编号时按序前置、未提及的候选保持原序续接，输出不可解析或超时则保持融合顺序。重排通过 `RETRIEVAL_RERANK_ENABLED` 按需开启，默认使用融合顺序以获得更低延迟。这类短结构化调用必须关闭思考链，否则推理过程会耗尽输出预算、返回空内容——"只用提示词约束不可靠、要在网关层设参数"由此成为网关层的一条硬规则。

与 5.5 的 Agent 链路形成分工：Agent 适合需要自主规划的多跳问题，固定链路适合单跳事实问题且延迟更可控，两者失败互相回退。

**评测。** 建立两套各 24 题的人工评测集（23 题语料可答），按 recall@k 与 MRR@k 衡量检索效果：

- **规范问法集**：题面直接采用规范文件用语，基线已达 recall@1 0.8696、recall@6 0.9130、MRR@6 0.8840，增强后各项指标与基线持平；
- **口语化问法集**：模拟学生日常提问（"预备党员要熬多久才能转正？""党内处分一共有哪几档？"），题面与原文措辞不一致，正是多查询改写要解决的问题。

| 口语化问法集 | recall@1 | recall@6 | MRR@6 |
|--------------|----------|----------|-------|
| 基线（单查询） | 0.5217 | 0.6087 | 0.5543 |
| 增强（多查询 + 加权 RRF） | 0.6522 | 0.7391 | 0.6848 |
| **提升** | **+13.0pp** | **+13.0pp** | **+13.0pp** |

多查询改写与加权 RRF 的组合把学生的口语提问翻译成规范用语后再检索，recall@1 与 recall@6 各提升 13.0 个百分点、MRR@6 提升 13.0 个百分点：学生用"熬多久转正"这样的问法，也能在第一位拿到《发展党员工作细则》的原文片段。评测脚本 `backend/scripts/eval_retrieval.py` 与两套评测集随仓库提供，一条命令即可复现。

### 5.14 关键技术十一：语义缓存与引用核验

**语义缓存。** 命中判定不看问题字面，而看问题嵌入的余弦相似度：相似度不低于 0.93 即复用已生成的带引用答案。缓存键包含分类与文档范围，只缓存"带引用、非降级"的知识库回答，避免把"资料不足"固化；存储与淘汰交给 cachetools 的 `TTLCache`（默认 1 小时、上限 200 条），嵌入模型不可用时自动退回规范化文本精确匹配。实测同一问题的近义问法第二次提问由 20 秒级降到 0.02 秒。

**引用核验。** 回答生成后把"答案块 + 其引用的片段"成批交给快模型逐块判断是否被直接支撑，剔除不被支撑的引用编号并重新编号；核验超时、输出不可解析或全部不通过时保留原答案并标记状态，不让核验本身成为失败原因。实测一次回答的 8 个引用块中核验剔除了 4 个仅"沾边"的引用，回答正文随之收敛。

### 5.15 关键技术十二：LLM 网关的可观测、熔断与额度

所有模型调用收敛到 `_post_chat` 一个出口，在这里统一完成四件事：

| 能力 | 实现 |
|------|------|
| 可观测 | 每次调用记录模型、时延、提示/生成 token 与成败，环形缓冲保留最近 500 条；累计成功率、平均时延与最近调用经 `/api/v1/ai/observability` 对外 |
| 熔断 | 连续 5 次上游失败打开 30 秒，期间快速失败；冷却后半开放行，成功即闭合。4xx（参数、鉴权问题）不计入失败，避免一次格式错误拖垮整条链路 |
| 额度 | 按用户自然日 30 万 token 计，管理员不受限，超额返回 429；统计按上游返回的 `usage` 计，缺失时按字符估算 |
| 模型分流 | 意图路由、查询改写、重排与引用核验等低复杂度调用走快模型，问答与报告生成走主模型 |

## 八、总结与展望

### 8.1 阶段性成果

项目围绕"思政实践从知识输入走向能力输出"这一目标，完成了六个可反复进入的功能模块（含成长社区）与一套可信的 AI 工程底座：128 个接口、104 项自动化测试全部通过、Ruff 静态检查零告警、13 个版本化迁移。

在 AI 侧，系统把"模型输出不可信"当作默认前提：白盒校验、逐句引用、无据拒答、失败显式化贯穿全部调用。在此基础上，自主检索 Agent 让模型可以规划检索与回看本人练习；RAG-Fusion 式多查询、语义缓存与引用核验让检索更准、更便宜、更可核查；统一 LLM 网关提供可观测、熔断与额度保护；安全网关守住输入输出的边界，图片与语音补上多模态入口，MCP 把知识库变成可被外部复用的标准工具——AI 从"回答问题"变成了"可以规划、可以取证、可以复用、可以度量"的工程组件。

### 8.2 演进路线

下一阶段沿以下六个方向推进：

| 方向 | 计划 |
|------|------|
| 知识库扩容 | 从 17 篇种子资料扩展到校史、党章全文与地方红色资源，配套版本化的资料审核流程 |
| 语音闭环 | 在语音合成之上补齐"语音作答 → 转写 → 评分"链路，把谈话与辩论延伸到口语场景 |
| 多模态审核 | 对进入对话的图片增加独立的内容安全审核环节，与文本安全网关共用规则库 |
| 教师端学情 | 把成长数据沉淀为按班级维度的学情图谱与预警看板 |
| 工具生态 | 以 MCP 为边界，把谈话、辩论等能力也工具化，接入更多校园 Agent 生态 |
| 生产加固 | 补齐域名与 HTTPS、监控告警与备份恢复，支撑真实的院系级使用 |

### 8.3 应用价值与推广

**面向学生**，把原本稀缺的一对一谈话练习变成随时可用的高频训练：不用等组织安排、不怕答错丢面子，练完有量化报告可回看。

**面向教师与院系**，任务与量规承担重复性的组织工作，学习档案让辅导从"凭印象"变成"看数据"；一名组织员可以同时带更多学生。

**面向推广**，知识库可直接替换为校史、党章与地方红色资源，六个模块的题型与话术集中在种子数据里，换一所学校只需换资料与场景文案；MCP 让知识库能作为标准工具被其他校园系统复用。

**成本上**，DeepSeek 按量计费 + 语义缓存 + 按用户日额度，学院级规模的使用成本可控；Docker Compose 一条命令完成部署，普通云主机即可承载。

**社会价值上**，思政实践长期集中在少数有师资、有资源的院校，本项目的目标是让"能练、能评、能追踪"的实践训练以低成本复制到更多学校，是教育数字化中一份可复用的样本。
